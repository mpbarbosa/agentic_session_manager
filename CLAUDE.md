# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Purpose

Agentic session manager that **monitors repositories and their evolution and status**. The first feature is a page to select a repository to monitor.

## Commands

```bash
npm run dev        # run API (tsx watch) + Vite web dev server together via concurrently
npm run dev:api    # API only, on API_PORT (default 3001)
npm run dev:web    # Vite web only, on port 5173 (proxies /api -> API_PORT)
npm run build      # tsc -b (typecheck via project refs) then vite build
npm run typecheck  # tsc -b --noEmit
npm start          # run the API without watch
npm run test       # vitest (pure helpers + adapters)
```

Tests run with **vitest** (`npm run test`, `npm run test:watch`). They cover the pure modules only — `server/pure.ts` and `src/overview.ts` — plus `src/adapters.ts`; there are no component or HTTP tests.

## Architecture

Two processes, split by tsconfig project references (`tsconfig.app.json` for the browser, `tsconfig.node.json` for the server):

- **Web** — Vite + React + TS + Tailwind (Material-ish design tokens) in `src/`. `App.tsx` is the container: it fetches from `src/api.ts`, holds the server-owned state (repos, overview rows, active repo, selected worktree, changes, commits, worktrees), and passes props down to presentational components — `Header`, `Sidebar`, `OverviewView`, `ChangesView`, `HistoryView`, `WorktreesView`, `BranchesView`, `CompareView`, `ReleaseView`, `SettingsView`, `TerminalDrawer`, and `Modals` (Add-repo + Toast). The set of tabs is the **`ViewId`** union in `src/types.ts` — declared once and imported by `App`, `Sidebar` and `Header`, because three inline copies of it is what made Overview and Branches collide in all three files when they were merged. `App.refreshRepos()` is the single place that re-fetches `GET /api/repos`, mapping the payload into *both* the sidebar's `Repository[]` and the Overview's `RepoOverviewRow[]` so the two views can't drift. The API types (`shared/types.ts`) are mapped into the components' view-model types (`src/types.ts`) by `src/adapters.ts`. No component calls the API directly. Vite (`vite.config.ts`) proxies `/api` to the API server.
- **API** — Express in `server/index.ts`. Reads the repo list from a **manual config file** (`repos.config.json`, override with `REPOS_CONFIG`), then enriches each entry with live git status by shelling out to `git` (`branch`, `status --porcelain` dirty count, last commit, `worktree list`). Every git call is wrapped so a missing path or non-repo degrades to `available: false` instead of throwing. Endpoints: `GET /api/repos` (list + `selectedId`; per-repo `status` carries `branch`, `dirtyCount`, `lastCommit`/`lastCommitSubject`/`lastCommitDate`/`lastCommitRelative`, `worktrees`, `available` — this one payload backs both the sidebar switcher and the **Overview**), `GET /api/repos/:id/status` (changed files, ahead/behind), `GET /api/repos/:id/log?limit=&all=` (recent commits, structured — includes author email + multi-line `%b` body, parsed via a per-commit record separator; `all=1` adds `git log --all`. Drives History's wired Style/`--all`/Limit/Run controls: Limit + `--all` re-fetch via `App.handleQueryLog`, Style is client-side row density), `GET /api/repos/:id/worktrees` (main + linked worktrees, parsed from `git worktree list --porcelain`; first entry is the main tree), `POST /api/repos/:id/worktrees` (create a linked worktree via `git worktree add` — body `{ path, branch }`; attaches an existing branch or creates a new one from HEAD; branch name allowlisted, `path.resolve` neutralizes leading-dash injection, refuses if the path exists), `GET /api/repos/:id/diff` (changed files with parsed unified diffs for the Changes view; untracked files rendered as whole-file adds; honors `?worktree`), `GET /api/repos/:id/commit/:hash` (full commit detail — metadata + per-file `git show` numstat/name-status paired by index + parsed diff; `:hash` restricted to hex so no arbitrary refs reach git; powers the History inspector + diff modal), `POST /api/repos/:id/checkout` (check out a ref in the main tree/`?worktree` — body `{ ref, worktree? }`; ref allowlisted + must resolve to a commit, refuses when the tree is dirty, a bare hash lands on a reversible detached HEAD), `GET /api/repos/:id/compare?base=` (divergence of every local branch + detached worktree HEAD against a base — default the main tree's branch: ahead/behind counts, `merge-base`, per-worktree `dirty` flag, and each ref's unique/ahead commits; all read-only `git rev-list`/`merge-base`. Powers the **Compare tab** (rows sorted main-first then most-divergent; per-row actions reuse the endpoints below — **Merge** a branch ahead of the base, **Prune**/delete a merged branch or worktree, copy the git name, and **⇥ base + Delete** to retire the checked-out merged branch)), `POST /api/repos/:id/prune-worktree` (remove a linked worktree via `git worktree remove` — body `{ path }`; validated against the repo's worktrees, refuses the main tree, **no `--force`** so git refuses a dirty tree. Compare-tab **Prune** button, shown only on a merged + clean worktree), `POST /api/repos/:id/delete-branch` (delete a merged local branch via `git branch -d` — body `{ branch }`; refuses the main branch, and `-d` (not `-D`) makes git itself refuse anything unmerged or checked out in a worktree. Compare-tab **Prune** button for a merged branch that has no worktree), `POST /api/repos/:id/merge-branch` (merge one local branch into another — body `{ branch, into }`; if `into` is checked out in a worktree it merges there (refuses dirty, aborts on conflict), otherwise merges in a **throwaway worktree** under `os.tmpdir()` so the user's working tree is never touched — handles fast-forward + merge commits, aborts + cleans up on conflict. Compare-tab **Merge** button on any branch ahead of the base; the base *is* the merge target), `POST /api/repos/:id/exec` (run a `bash -c` command in the repo/`?worktree` dir for the Terminal drawer — `runShell` with `childEnv()`, 20s timeout, 1MB cap; returns `{ code, output, cwd }`; **arbitrary RCE by design** — see security note), `GET /api/health` (real runtime info — node/platform/arch/uptime/host:port/repoCount — powers the Settings → API Server panel), `POST /api/repos/:id/merge-worktree` (merge a linked worktree's branch into the main working tree via `git merge --no-edit` run in the main tree; refuses if the target is dirty, aborts on conflict so main is never left half-merged; validated against the repo's worktrees), `POST /api/repos/:id/commit` (stage all + commit; body `{ message?, worktree? }` — a non-empty `message` is used **verbatim**, otherwise the server AI-generates one via Claude/`claude-opus-4-8`; message generation computes the diff *without* touching the index, so a failure leaves the tree unstaged; honors `?worktree` via body), `POST /api/repos/:id/commit/message` (preview an AI-suggested commit message from the current diff **without committing** — powers the Changes view's "AI Commit" generator; shared `generateOrThrow` helper + `CommitMsgError` map auth/model failures to 401/502), `POST /api/repos/:id/push` (push the **main** working tree's branch to `origin` via `git push origin <branch>`; validates a main tree + `origin` remote exist; refuses if detached; UI shows the Push button only on the main tree, gated behind a confirm), `GET /api/repos/:id/graph?style=plain|pretty|forest&all=&decorate=&oneline=&graph=&limit=` (git-log graph; `plain` = raw flags, `pretty` = fixed colored `--format` with `--color=always`, `forest` = shells out to `git-foresta`/`git-forest` if on PATH else `forestAvailable:false`; all flags allowlisted — no user strings reach git; ANSI output rendered client-side by `AnsiText.tsx`. Surfaced by History's **List/Graph toggle** (`App.handleLoadGraph` → `fetchGraph`): Graph mode renders `pretty` (`git log --graph`, always available) or `forest` (git-foresta; graceful "not installed" note + fall back to pretty when `forestAvailable:false`)), `GET /api/browse?path=` (filesystem picker — lists a directory's sub-folders with a per-entry `isGitRepo` flag; backs the Add-repo modal's **folder-picker dialog** (`FolderPicker` in `Modals.tsx` via `browseDir`), so a repo can be chosen by navigating the filesystem instead of typing an absolute path), `POST /api/repos` (add a local repo, which also becomes selected), `PUT /api/selection` (persist `{ id: string | null }`), `PUT /api/selection/worktree` (persist the active worktree `{ path: string | null }`; validated against the selected repo's worktrees), and the **release pipeline** endpoints (see below).

**Release pipeline (tests → commit → merge → bump → push → deploy):** `GET /api/repos/:id/test-runners` detects how to run the repo's tests, ranked (`docker-script` for `scripts/docker-test.sh` etc.; `npm` for `test`/`test:ci`/`test:unit`/`test:e2e`; `other` for go/cargo/pytest/Makefile). `GET /api/repos/:id/deploy-runners` likewise detects a **deploy** command (npm `deploy`/`release`/`publish`/`ship` scripts → `scripts/deploy.sh`/`deploy.sh` → platform configs `fly.toml`/`vercel.json`/`netlify.toml`/`wrangler.toml`); the Release view defaults its deploy command from this — **empty when none detected**, so the opt-in deploy step just skips rather than failing on a bogus default. `POST /api/repos/:id/pipeline` `{ command, push, worktree, deploy }` starts a **streamed job** (in-memory `jobs` Map, `crypto.randomUUID` id). **The steps deliberately split between the selected worktree and main** (`runPipeline`): (1) **tests** — `spawn("bash", ["-c", command], {detached})` in the **selected worktree**, streaming stdout/stderr, **fail-fast** on non-zero exit; (2) **commit** — AI commit (`generateCommitMessage` + `git add -A`/`commit`) **in the worktree** (skipped if clean; captures the diff for the bump); (3) **merge** — `git merge --no-edit <worktreeBranch>` into **main** (skipped when already on main; refuses if main is dirty; aborts on conflict); (4) **bump** — in **main**: `decideBump` sends the captured diff to Claude (`claude-opus-4-8`) → major/minor/patch, applied to main's `package.json`, committed as `chore: bump version to X`; (5) **push** — `git push origin <mainBranch>` from **main** (skippable; on a **clean tree** it still pushes when the branch is merely *ahead of origin* — `commitsAheadOfOrigin` — so already-committed-but-unpushed work still ships instead of being reported "nothing to release"); (6) **deploy** — an **opt-in** deploy command run from **main** (streamed like the tests step via `runStreamed` + `childEnv()`; skipped when the request carries no `deploy` command; a non-zero exit fails the run; **arbitrary RCE by design** — see security note). Bump/merge/push/deploy never run in the worktree. `GET …/pipeline/:jobId/stream` is **SSE** (`text/event-stream`): replays buffered `PipelineEvent`s then streams live `step`/`log`/`done`. `POST …/pipeline/:jobId/cancel` kills the process group. UI: a **Release view** (`components/ReleaseView.tsx`, threaded `repoId` + `selectedWorktree` + `onRefresh`) with a runner select + editable command, a push checkbox, an opt-in **"Deploy after push"** checkbox + deploy-command input, a confirm, live ANSI console (`AnsiText`), a per-step progress bar (Tests/Commit/Merge/Bump/Push/Deploy) that surfaces each `step` event's `detail`, and Stop (consumes the stream via the browser `EventSource`).

**Overview (fleet view over all configured repos):** `components/OverviewView.tsx` renders every repo from `GET /api/repos` in one sortable table — name + description, branch, dirty count, last-commit subject + relative age, worktree count — over a summary strip (dirty repos/files, repos stale >90d, linked worktrees, unavailable). It is the **landing view when `selectedId` is null**; with a selection persisted, the initial load switches straight to History as before. Clicking a row calls `App.selectRepoById` → the existing `selectRepo`, so the per-repo tabs behave exactly as they always did. All the filter/sort/summary logic lives in **`src/overview.ts`** as pure functions (`filterRepos`, `sortRepos`, `nextSort`, `visibleRepos`, `summarize`, `filterRepositories`) with no React or fetch imports, unit-tested in `src/overview.test.ts`; `toOverviewRow` in `src/adapters.ts` maps one API `Repo` to a row (parsing `lastCommitDate` into epoch ms for sorting, `null` when unknown). Default sort is **stalest-first**; repos with no known commit date sink to the bottom in *both* age directions. The sidebar switcher (`Sidebar.tsx`) has its own filter box + scroll cap + "Browse all in Overview" link, since a flat 105-entry dropdown is unusable.

**Branches:** `components/BranchesView.tsx` lists every local branch for the active repo, newest commit first, from `GET /api/repos/:id/branches` (`fetchBranches` → `App.handleLoadBranches`). Per row: branch name, a **CURRENT** badge for the checked-out branch and a **WORKTREE** badge when it is checked out in a linked worktree, upstream (`synced` / `local only` / `gone`) with ahead/behind, and the last commit's short hash, subject and relative age. Read-only — it reports, it does not merge or delete; the destructive branch actions live in the **Compare** tab.

⚡ **`GET /api/repos` performance — the cost is git *process spawns*, not git's work.** Measured on 105 local repos: each extra `git` invocation inside `readStatus` costs ~250ms of wall clock across the fleet, and that cost is **the same whether the calls run in series or concurrently** (making the original four sequential calls concurrent changed nothing — the machine is spawn-bound, not latency-bound). So `readStatus` minimises *invocations*: `git status --porcelain=v1 -b` yields the branch **and** the dirty count in one spawn (replacing a separate `rev-parse --abbrev-ref HEAD`, which also fixes repos with no commits yet — `parseBranchLine` handles "No commits yet on main"), `git log -1 --pretty=<LAST_COMMIT_FORMAT>` packs hash/subject/ISO date/relative date into one `\x1f`-separated line (`parseLastCommit`), and the worktree paths are read off the filesystem by `readWorktreePaths` — `.git` is a directory for a main checkout, or a file reading `gitdir: <common>/worktrees/<name>` for a linked one (`commonGitDirFromGitFile`), from which `<common>/worktrees/*/gitdir` enumerates the set (`worktreePathFromGitdir`). That fs read was verified to match `git worktree list --porcelain` exactly across all 105 repos. Net: **~1.75s → ~0.75s warm / ~0.81s cold.** There is deliberately **no caching layer** — the measurement didn't justify one.

⚠️ **Security (this API is unauthenticated and powerful — RCE via the pipeline **and the Terminal exec endpoint**, filesystem read via `/browse`, git push, billable Claude calls):**
- The server **binds to `127.0.0.1` by default** (`HOST = process.env.API_HOST ?? "127.0.0.1"`) so it is not LAN-reachable. Overriding `API_HOST` without adding your own auth re-opens unauthenticated RCE — don't.
- The Vite proxy targets **`http://127.0.0.1:...`** (not `localhost`) to match the IPv4 loopback bind.
- The pipeline's test step runs the repo's own command (arbitrary code). Its child env is sanitized by `childEnv()` — `ANTHROPIC_API_KEY`/`ANTHROPIC_AUTH_TOKEN` are **stripped** so a test script can't exfiltrate the key loaded from `.env`. The command is always detected + shown + confirmed, never inferred-and-run silently. The optional **deploy** step is the same posture — an arbitrary command run from **main**, off by default, `childEnv()`-sanitized, and spelled out in the confirm dialog before it runs.
- `POST /api/repos/:id/exec` (the Terminal drawer) runs an arbitrary `bash -c` command in the repo/worktree dir via `runShell` — same `childEnv()` stripping, plus a 20s timeout and 1MB output cap. This is deliberate RCE, tolerable **only** because of the localhost bind; do not expose it.

**Active worktree:** config also holds `selectedWorktree` (a path; null = main tree). The status/log/graph endpoints accept `?worktree=<path>` and run git in that directory *only if* it's a real worktree of the repo — `resolveWorktreePath` validates against `git worktree list` and otherwise falls back to the repo's main path (never runs git in an arbitrary dir). Switching repos (`PUT /api/selection`) resets the active worktree to main. The frontend threads `selectedWorktree` into status/graph fetches so Changes/History reflect the chosen worktree; clicking a row in the Worktrees tab sets it.

Config writes go through `saveConfig`, which writes a temp file then `rename`s it — an **atomic write** so concurrent readers (e.g. a status request firing alongside a selection write) never observe a truncated file.
- **Shared** — `shared/types.ts` holds the `RepoConfigEntry` / `RepoStatus` / `Repo` contract, imported by both sides (with `.ts` extensions, resolved by the bundler / tsx).

Data flow: `repos.config.json` → `loadConfig()` → per-repo `readStatus()` (git shell-outs) → `GET /api/repos` → React UI.

## Conventions & gotchas

- **Do not read `process.env.PORT` in the API** — the preview/launch harness injects `PORT=5173` (Vite's port). The API uses `API_PORT` specifically to avoid colliding with the web server.
- To add a monitored repo, append an entry to `repos.config.json` (`id`, `name`, and optional `path`/`description`/`url`); no code change needed. A repo without a local `path` shows as unavailable (no git status).
- `repos.config.json` also holds a top-level `selectedId` — the persisted "active repo". The API clears it on read if it points at a repo that no longer exists.
- TS is configured with `allowImportingTsExtensions`, so intra-project imports include the `.ts`/`.tsx` extension.
- `npm install` may leave esbuild's postinstall unapproved (allow-scripts guard); Vite needs it. Approved via the `allowScripts` block in `package.json`.
- The AI commit-message feature (`POST /api/repos/:id/commit`) uses the `@anthropic-ai/sdk` from the **API server process** — it needs `ANTHROPIC_API_KEY` (or an `ANTHROPIC_AUTH_TOKEN` / `ant auth login` profile) in that process's environment. Without it the endpoint returns a friendly 401 and never stages/commits. `new Anthropic()` is constructed lazily inside the handler so the server still boots without credentials.
